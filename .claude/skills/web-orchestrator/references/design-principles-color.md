# Design Principles — Color (색상)

팔레트 구성·색 조화·스케일 설계·semantic color·대비·다크 모드의 규칙이다.

## 팔레트 구성 — 역할 분담

- **4계층 구성**: neutral 1벌 + primary 1개 + semantic 4개(success/warning/error/info) + accent 0~2개. 각 색은 8~10단계 음영이 필요하다 — 5색 무드보드식 팔레트는 실전에서 부족하다 (Refactoring UI).
- **neutral(회색)이 화면의 90%. 회색부터 만든다** — 본문·배경·카드·보더·비활성·폼이 전부 회색 계열. 색은 정보와 액션에만 쓰여야 신호가 된다. 회색에 브랜드 hue를 미량(chroma 0.01~0.03) 섞으면 온도감이 생긴다 (Radix slate/sage 방식).
- **60-30-10 비율**: 60% 배경 neutral, 30% surface/구조, 10% 액센트(CTA·링크·활성). 액센트의 힘은 희소성에서 나온다 — primary가 화면 곳곳에 있으면 "여기를 눌러라" 신호가 사라진다.
- **색 하나당 기능 스케일 부여** (Radix 12단계 매핑): 1~2 앱/서브틀 배경 · 3~5 컴포넌트 배경/hover/active · 6~8 보더(8=포커스 링) · 9~10 solid 배경(10=hover) · 11 저대비 텍스트 · 12 고대비 텍스트.

## 색 조화 (Color Harmony)

- **색상환 조화(보색/유사색/삼각)는 hue 선택의 출발점일 뿐, 그대로 쓰지 않는다** — 풀 채도 + 동일 명도의 보색·삼각 조합은 대면적 UI에서 시각적 진동을 만든다. 조화 이론은 명도/채도 조절 없이는 인터페이스에서 실패한다.
- **실전 조화는 hue 수 제한(브랜드 hue 1~2개) + 채도·명도 통제로 만든다** — M3는 primary(chroma 48)와 secondary(chroma 16)를 같은 hue에서 채도만 바꿔 파생한다. 예: primary `oklch(0.55 0.18 250)` → secondary `oklch(0.55 0.06 250)`.
- **보색은 소량 액센트 전용(면적 10% 미만), 유사색(인접 30° 이내)은 배경·구조에 안전** — 보색은 CTA 강조엔 좋지만 넓게 쓰면 공격적이다.

## 색상 스케일 설계 (50~950)

- **스케일은 OKLCH로 만든다** — HSL의 L은 인지 명도가 아니다(같은 L=50%라도 노랑은 밝고 파랑은 어둡게 보임). OKLCH의 L은 모든 hue에서 균일해 같은 L이면 대비가 동일하게 유지된다 (Evil Martians).
- **명도 곡선: L을 거의 균등 간격 배치** — L ≈ 0.98(50) → 0.93(100) → 0.87(200) → 0.79(300) → 0.70(400) → 0.60(500) → 0.51(600) → 0.42(700) → 0.35(800) → 0.28(900) → 0.22(950). "hover에 한 단계 어둡게" 규칙이 모든 색에서 동일하게 작동한다.
- **채도 곡선은 종 모양**: 중간(400~600) 최대, 양끝 감소 — chroma 0.02(50) → 0.15(500) → 0.07(950). 양끝에서 채도를 유지하면 형광/탁색이 된다.
- **밝은 단계로 갈수록 hue를 '밝은 hue' 쪽으로 소폭 회전(±5~15°)** — 채도만 낮추면 탁해진다 (Refactoring UI). 예: orange-100은 노랑 쪽, orange-900은 빨강 쪽.
- **생성기를 맹신하지 않는다** — 중간 base(브랜드색=500) → 양끝(최암/최명을 실제 용례로 확정) → 사이 보간 → 눈으로 보정.

## Semantic Color

- **관례 준수**: success=green, warning=amber, error=red, info=blue. 예: `#16A34A / #D97706 / #DC2626 / #2563EB` (Tailwind 600 계열).
- **semantic도 최소 4토큰 스케일**: subtle-bg / border / solid / text. 예: error-bg `#FEF2F2`, error-border `#FCA5A5`, error-solid `#DC2626`, error-text `#991B1B`. warning은 노랑 solid 위 흰 텍스트가 불가하므로 amber-50 배경 + amber-800 텍스트가 기본.
- **색만으로 상태 전달 금지 (WCAG 1.4.1). 항상 아이콘+텍스트 병행** — 남성 약 8%가 적녹색약. 에러 필드 = 빨간 보더 + 아이콘 + 구체적 메시지. 차트 = 색 + 패턴/라벨.

## 대비 (Contrast)

- **WCAG AA**: 일반 텍스트 4.5:1, 큰 텍스트(24px+ 또는 18.66px bold+) 3:1. 예: 흰 배경 위 `#767676`이 4.5:1 경계, gray-400(`#9CA3AF`)은 2.8:1로 본문 불합격 — placeholder에도 위험. 예외: 로고·비활성·장식.
- **비텍스트 3:1 (SC 1.4.11)**: UI 컴포넌트 경계·아이콘·포커스 링·차트 요소는 인접색과 3:1. 흰 배경 위 인풋 보더는 `#949494` 이상 — gray-300은 1.5:1로 불합격이므로 배경색 차이 등 다른 식별 수단 병행.
- **APCA를 설계 감각으로 병용** — WCAG 2 산식은 다크 배경에서 대비를 과대평가한다. 준수는 WCAG 2.x로, 다크 모드 검증은 APCA(Lc 75=body 최소, 60=큰 텍스트, 45=헤드라인)로 이중 체크.

## 다크 모드

- **반전이 아니라 재설계다. 배경은 순검정이 아닌 `#121212` 계열** — 순검정 위 순백은 halation이 심하고 elevation 계층을 만들 수 없다. 예: 배경 `#121212`, 카드 `#1E1E1E`, 모달 `#2C2C2C`.
- **elevation은 그림자가 아니라 표면 밝기로** — 어두운 배경에서 그림자는 보이지 않는다. M2 white overlay: 0dp 0% → 1dp 5% → 6dp 8% → 12dp 11% → 24dp 16%. M3는 surface-container(lowest→highest) 역할 토큰.
- **채도를 낮춘 밝은 톤 사용** — 고채도 색은 어두운 표면에서 진동하고 대비가 부족하다. M3: primary tone 40(라이트) → tone 80(다크). Tailwind식: blue-600 → blue-400.
- **다크 텍스트는 흰색 불투명도 계층**: 87% / 60% / 38%. 100% 순백은 눈부시다.

## 색의 심리·기능

- **확신 없으면 primary는 파랑** — 신뢰 연상이 강하고 문화권 간 부정 연상이 적으며 적녹색약에서 비교적 안전 (SaaS 기본값이 된 이유). 단 파랑이 신뢰를 만들지는 않는다.
- **브랜드 색과 액션 색을 분리할 수 있어야 한다** — 브랜드가 빨강·노랑이면 CTA에 그대로 쓸 때 error와 충돌하거나 대비가 부족하다. 브랜드 색은 로고·마케팅 표면에, 액션 색은 접근성 기준을 통과하는 별도 색으로.
- **빨강은 destructive 액션 전용으로 아껴 쓴다** — 장식·강조로 남용되면 위험 신호가 소멸한다(희소성 원리). "삭제"는 red-600 solid 또는 red 텍스트 + confirm. 일반 취소 버튼은 neutral — 빨간 취소 버튼 금지.
