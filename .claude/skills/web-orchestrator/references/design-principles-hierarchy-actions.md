# Design Principles — Hierarchy & Actions (시각 위계·정렬·버튼/CTA 배치)

시각 위계 도구, 스캐닝 패턴, 버튼 위계·배치, Fitts's Law, CTA 가시성, 정렬, 파괴적 액션의 규칙이다.

## 시각 위계 5도구

위계는 다음 5가지 도구의 조합으로 만든다 (NN/g):

1. **크기** — 중요할수록 크게, 단계는 2~3개면 충분. 예: 페이지 제목 > 섹션 제목 > 본문.
2. **굵기** — 크기를 더 키울 수 없을 때 bold로. 예: 테이블에서 핵심 컬럼만 semibold.
3. **색 대비** — 가장 채도 높은 색 1가지를 최상위 액션 전용으로 예약. 색을 여러 곳에 쓰면 위계가 사라진다.
4. **위치** — 중요한 것은 위·왼쪽(LTR). 시선은 좌상단에서 시작하고 수평 주의력은 왼쪽으로 치우친다.
5. **여백** — 강조 요소 주변에 더 많은 공간. hero CTA 주위 여백은 본문 요소 간격의 2배 이상.

**불변식: 한 화면(뷰포트)에 primary 강조는 1개.** 강조 후보가 2개면 하나를 secondary로 강등하거나 다음 화면으로 내린다. 모든 것이 강조되면 아무것도 강조되지 않는다.

## 스캐닝 패턴

- **텍스트 헤비 페이지는 F-pattern을 전제로 front-loading** — 문단·불릿·소제목의 첫 2~3단어에 정보를 담는다. 뒤로 갈수록 읽히지 않는다 (NN/g 눈추적).
- **F-pattern은 위계 실패의 증상 — 위계로 이긴다** — 의미 단위마다 소제목을 넣으면 layer-cake 스캐닝(제목만 훑고 필요한 층에서 정독)으로 바뀐다.
- **Z-pattern은 텍스트가 적은 랜딩/히어로에만** — 실증된 법칙이 아니라 저밀도 레이아웃용 휴리스틱이다. 로고(좌상)→내비(우상)→비주얼→CTA(우하).
- **이미지-텍스트 지그재그 교차 배치 금지** — 스캔 동선이 길어진다. 피처 소개 섹션은 텍스트 열을 한쪽으로 고정.

## 버튼 위계

- **3단계 고정**: primary=filled / secondary=outlined(tonal) / tertiary=text. filled는 "플로우를 완결하는 액션(저장·확인)", text는 다이얼로그·카드 내 저우선 액션 (M3·HIG·Fluent 공통).
- **한 컨텍스트(다이얼로그·폼·카드·화면 영역)에 primary는 정확히 1개** — 나란한 두 액션이 동급이면 둘 다 outlined로.
- **destructive는 primary 스타일 재사용 금지, 전용 danger 스타일(red)** — brand색 filled 삭제 버튼은 습관적 클릭을 유발한다.

## 버튼 배치

- **다이얼로그: 웹은 우측 primary(`[취소] [저장]`)를 기본값으로, 제품 전체에서 절대 섞지 않는다** — 좌/우 어느 쪽이 우월하다는 실증 근거는 없고 플랫폼 관례 + 일관성이 유일한 규칙 (NN/g OK-Cancel). 웹은 우측이 지배적 관례.
- **페이지 레벨 단일 컬럼 폼: 제출 버튼은 마지막 필드 바로 아래, 필드의 왼쪽 라인 정렬** — 입력과 액션이 하나의 수직축을 이루면 완료 경로가 명확하고 화면 확대 사용자가 버튼을 놓치지 않는다 (Adam Silver/GOV.UK). 다이얼로그(우측)와 페이지 폼(좌측)의 문맥을 구분한다.
- **폼의 secondary 액션은 primary 옆이 아니라 위/아래 분리 또는 링크로 강등** — 제출 직전에 동급 선택지가 나란하면 오클릭 유발. 예: "저장" 아래 "취소" 텍스트 링크.
- **모바일 주요 액션은 화면 하단 1/3(thumb zone)** — 조작의 75%가 엄지 주도 (Hoober 연구). 모바일 폼 제출은 풀폭 하단.
- **sticky bottom action bar는 '긴 스크롤 + 단일 주행동' 화면에만** — 상품 상세·체크아웃처럼 다음 행동이 하나일 때. 남용하면 콘텐츠를 가리고 위계를 평탄화한다.

## Fitts's Law 적용

- **화면 모서리·가장자리는 '무한 크기' 타깃** — 포인터가 멈추므로 오버슈트 불가. 전역 컨트롤을 붙인다. (터치스크린에는 성립하지 않음)
- **자주 쓰는 액션은 크게 + 직전 인터랙션 지점 가까이** — 인라인 편집의 저장 버튼은 필드 바로 옆에.
- **위험 액션은 작게, 멀리, 흐름 밖에 (역적용)** — "전체 삭제"는 자주 쓰는 "추가" 옆이 아니라 overflow 메뉴 하단에 분리 (NN/g Dangerous UX).

## CTA 가시성

- **above the fold는 여전히 유효(약화됐을 뿐)** — 첫 화면이 시청 시간의 57%, 두 화면까지 74% (NN/g). 핵심 가치 제안과 첫 CTA는 첫 화면에, 긴 설득이 필요한 페이지는 말미에 동일 CTA 반복.
- **가시성은 위치보다 대비로** — 배경·주변과의 명도/채도 차이를 확보하고 그 색을 다른 데 쓰지 않는다. 무채색 UI에 단 하나의 brand색 버튼.
- **버튼 라벨은 '동사 + 결과'** — 라벨만 읽고 클릭 결과를 알 수 있게. "확인" → "게시하기", "Submit" → "무료로 시작하기". 제네릭 라벨은 추가 사고를 요구하고 스크린리더 사용자는 같은 라벨 여러 개를 구분할 수 없다.

## 정렬

- **세로 정렬선(alignment line) 수 최소화 — 모든 요소는 기존 정렬선에 스냅** — 정렬선 하나가 시선 경로 하나다. 카드 내부의 제목·본문·버튼을 같은 좌측선에. 가운데 정렬 남용 금지(줄마다 시작점이 달라져 정렬선이 사라짐).
- **폼 라벨은 top-aligned 기본** — 라벨과 인풋을 한 번의 시선 이동으로 포착, 완료 시간 최단 (Penzo 눈추적). 번역·모바일 폭에도 안전. 예외: 값 비교·스캔이 잦은 밀집 설정 화면은 left-aligned가 유리.
- **기하학적 정렬이 어긋나 보이면 optical alignment로 마무리** — 수치상 중앙 ≠ 시각적 중앙. play 삼각형은 원 안에서 살짝 오른쪽, 불릿·따옴표는 내어쓰기.

## 파괴적 액션

- **confirm dialog에서 안전한 선택지를 default로** — Enter가 삭제를 실행하지 않게. `[취소(default)] [삭제(red)]` (Apple HIG·NN/g).
- **확인 버튼 라벨에 행동을 그대로 — "확인/예" 금지** — 질문("정말 삭제할까요?")과 버튼("삭제")이 호응해야 습관적 클릭을 끊는다. 대상·수량 명시: "항목 12개를 삭제합니다 → [취소] [12개 항목 삭제]".
- **파괴 버튼은 색·거리 이중 분리** — 확인성 액션과 멀리 두고 색으로도 구분. 하나의 신호(색만)로는 부족 (NN/g).
- **confirm보다 undo 우선, 최고 위험에만 type-to-confirm** — confirm 남발은 자동 클릭 습관을 만들어 효력을 잃는다. 되돌릴 수 있으면 즉시 실행 + undo 토스트(Gmail), 되돌릴 수 없는 것에만 이름 입력 확인(GitHub 저장소 삭제).
