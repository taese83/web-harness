# UX Brief — 도서관 열람실 좌석 예약 웹앱

## Reference Service Analysis
발산 조사 프로토콜(`design-principles-research.md`)에 따라 네 축에서 조사했다. 특정 서비스명은 각 축의 예시일 뿐 조사를 한정하지 않는다.

| 축 | Service | Strengths | Weaknesses | Patterns to Adopt |
|---|---|---|---|---|
| 동종(관습) — 좌석/공간 예약 | 스터디카페·독서실 예약 앱류(굿리치 등), 대학 도서관 좌석 배정 시스템 | 좌석 배치도를 그대로 시각화해 위치를 직관적으로 이해시킴, 남은 시간을 항상 노출 | 배치도가 실제 열람실과 다르면 혼란, 소형 화면에서 좌석 밀집 시 탭 오차 발생 | 좌석 배치도 은유(그리드가 아닌 실제 공간 배치) + 상태별 색상 구분 |
| 이종(영감) — 좌석 선택 UI | 영화관 좌석 선택(CGV/메가박스류) | 선택 즉시 시각 피드백(선택/불가/내 좌석 색 구분)이 명확, 확정 전 요약 바(선택 좌석 수·가격)로 실수 방지 | 영화관은 단일 회차라 시간 슬롯 개념이 없어 그대로 이식 불가 | "선택 → 하단 고정 확정 바" 패턴, 색+아이콘 이중 신호로 접근성 확보 |
| 트렌드 — 실시간 가용성 slot picker | 예약 캘린더형 slot picker(회의실 예약, 미용실 예약 등) | 시간 슬롯을 그리드가 아닌 타임라인으로 보여줘 "30분 단위" 같은 세분 단위를 스캔하기 쉬움 | 슬롯이 많아지면 스크롤 피로, 모바일에서 가로 스크롤은 발견성이 낮음 | 좌석×시간 2차원 그리드 대신 "좌석 선택 → 해당 좌석의 오늘 남은 슬롯만 세로 목록"으로 단순화 검토 |
| 시스템 릴리스 — 모바일 OS 관례 | iOS/Android 최근 네이티브 리스트·필터 패턴(HIG/Material 최신) | 하단 고정 primary action, 스켈레톤 로딩, pull-to-refresh 관례가 이미 학습되어 있음 | 웹은 pull-to-refresh를 기본 제공하지 않아 별도 구현 필요 | 하단 고정 예약 확정 바, 명시적 새로고침 버튼(자동 갱신 Should) |

공통 시사점: 좌석 수가 많아질수록(도서관 열람실 특성상 50~300석) "그리드 전체 스캔"보다 "가용 여부를 색으로 빠르게 구분 → 선택 시 상세(해당 좌석의 오늘 남은 슬롯)를 보여주는" 2단계 구조가 1분 이내 완료 목표에 유리하다.

## User Flow
```
[앱 진입]
  └─ 로그인 안 됨 → PAGE-001 로그인
        └─ 인증 성공 → PAGE-002 좌석 현황
        └─ 인증 실패 → PAGE-001 (인라인 에러, 재시도)
  └─ 로그인 됨(세션 유효) → PAGE-002 좌석 현황

[PAGE-002 좌석 현황]
  └─ 좌석 탭 → 해당 좌석의 오늘 남은 슬롯 표시(인라인 확장 또는 하단 시트)
        └─ 슬롯 선택 → 하단 고정 확정 바 활성화
              └─ [예약하기] 탭 → 성공 → 좌석 상태 "내 예약"으로 갱신 + 확정 피드백
                                → 충돌(이미 예약됨) → 안내 + 화면 자동 재조회
  └─ 내 예약 좌석 탭(이미 보유) → 취소 액션 노출
        └─ [취소] 탭 → 확인 다이얼로그
              └─ 확인 → 취소 완료 → 좌석 재예약 가능 상태로 갱신
              └─ 닫기/취소 → 변화 없음, 포커스 트리거로 복귀
  └─ 세션 만료 감지(API 401) → PAGE-001로 이동 + 안내
```

## Design Direction
- 브랜드 제약: 없음(도서관 로고/색상 지정 없음) — `ASSUMPTION(시안 확정)`: 공공기관 성격에 맞는 차분한 단일 accent color를 발산 조사 후 제안.
- 참조 무드: 영화관 좌석 선택 UI의 "선택 즉시 명확한 시각 피드백 + 하단 고정 확정 바"를 좋아할 근거(핵심 성공 조건이 속도)로 채택.
- 밀도: `ASSUMPTION(시안 확정)` — 표준 밀도. 근거: 도서관 회원은 연령대가 다양해(요청에 특정되지 않음) 과도한 고밀도는 오독 위험이 있으나, 좌석 수가 많아(NFR max fixture 300석) 완전 여백 중심도 스캔 비용을 늘린다.
- 다크모드: `ASSUMPTION(시안 확정)` — 불필요. 근거: 주간 열람실 이용·짧은 조회/예약 플로우로 야간 장시간 사용 근거가 없다.
- 주 사용 기기: 모바일 브라우저(요청에 명시). 데스크톱/태블릿은 보조 지원.
- 용어·문구 톤: 존댓말·간결체(공공 서비스 관례). 도메인 용어(좌석, 열람실, 슬롯→"이용 시간")는 회원이 이해하는 일상어로 표기하고 "슬롯" 같은 내부 용어는 UI 문구에 노출하지 않는다.

## Navigation & Responsive Strategy
- 구조 선택: 최상위 목적지가 로그인 후 좌석 현황 1개뿐이라 사이드바/톱바 메뉴/바텀 탭이 불필요하다(`design-principles-navigation-ia.md` 기준 — 항목 수 1개는 어떤 내비게이션 패턴의 임계치도 넘지 않음). 상단에는 최소 상태 표시(로그인 회원 식별 최소 정보 + 로그아웃)만 둔다.
- 반복 핵심 과업 1클릭 원칙: 좌석 현황이 로그인 직후 첫 화면이므로 별도 진입 클릭이 없다(이미 1클릭 이내).
- 모바일/태블릿/데스크톱 reflow: 모바일 = 좌석 그리드 세로 스크롤 + 하단 고정 확정 바. 태블릿/데스크톱 = 그리드 열 수만 확장, 하단 고정 바는 유지(작은 화면 패턴을 그대로 확장 — 별도 데스크톱 전용 레이아웃을 새로 설계하지 않음, ASSUMPTION: 보조 지원 수준이라는 NFR-002 범위와 일치).

## Key Interaction Patterns
- 좌석 선택: 탭하면 해당 좌석의 오늘 남은 슬롯이 인라인 확장(참조 화면 유지가 필요한 작업이므로 modal이 아니라 인라인/드로어 — `design-principles-interaction-controls.md` 기준).
- 슬롯 선택 → 확정: 하단 고정 바에 선택 요약과 [예약하기] 버튼(영화관 좌석선택 패턴 차용).
- 예약 확정: honest loading(낙관적 갱신 금지) — 동시성 충돌 가능성이 있어 성공 확률이 높다고 단정할 수 없는 작업이므로 `interaction-controls.md`의 "결제·삭제·복잡한 서버 검증은 honest loading" 원칙을 준용.
- 취소: confirm dialog(즉시 실행+undo 대신) — Open Decisions의 ASSUMPTION 근거 참고. dialog는 X버튼·Esc·바깥 클릭(파괴적 확인이므로 바깥 클릭은 제외)로 닫히고 포커스는 트리거로 복귀.
- 새로고침: 수동 새로고침 버튼(Should) — 자동 폴링 주기는 NEEDS_DECISION(API 부하 허용치 불명)이라 Phase 1에서는 수동 갱신을 Must 대체 수단으로 둔다.
- 로딩: 최초 진입은 스켈레톤(좌석 그리드와 동일 크기/위치, CLS 없음), 재조회는 상단 미세 인디케이터, 예약/취소 버튼은 100ms 이내 pressed 피드백.

## UX Check
- 첫눈에 알 수 있어야 하는 것: 지금 바로 예약 가능한 좌석이 어디인지(색+아이콘 이중 신호), 내가 이미 예약을 가지고 있는지.
- 다음 행동이 보이는가: 좌석 선택 → 슬롯 선택 → 하단 고정 [예약하기] 버튼이 항상 보여 다음 행동이 명확하다. 예약 후에는 [취소] 진입점이 내 예약 좌석에 상시 노출된다.
- 실수하거나 오해할 지점: (1) 지난 시간 슬롯과 "타인이 예약한" 슬롯을 색만으로 구분하면 오해 가능 — 라벨/아이콘 병기 필요. (2) 동시성 충돌 발생 시 "내가 실수한 것"으로 오인할 수 있어 문구에 "다른 회원이 먼저 예약했습니다"로 원인을 명시해야 한다. (3) 취소 확인 다이얼로그 문구가 모호하면 회원이 실수로 예약을 잃을 수 있어 좌석 번호·시간을 다이얼로그에 그대로 노출해야 한다.
- 먼저 정할 방향: 좌석×시간을 2차원 그리드로 한 화면에 다 보여줄지, "좌석 선택 → 해당 좌석 슬롯" 2단계로 나눌지(위 Reference Service Analysis 시사점). 1분 목표에는 2단계가 유리해 보이나 좌석 수가 적으면(NEEDS_DECISION 대상은 아니지만 확인 필요) 2차원 그리드가 더 빠를 수 있다.
- prototype/Phase 2에서 확인할 것: 실제 좌석 수 규모에 따른 그리드 vs 2단계 선택의 task timing 비교, 취소 confirm dialog의 실수 방지 효과, 색맹 사용자 대상 이중 신호 인지 테스트.

### Critical States & Annotation Intent
| Surface/annotation | normal/edge state | User intent | Error prevention | Verification |
|---|---|---|---|---|
| 좌석 그리드 | 동시성 충돌(edge) | 빈 좌석인 줄 알고 선택했으나 확정 시점에 이미 타인이 선점 | 확정 버튼 클릭 시 honest loading으로 최신 상태 재확인 후 커밋, 실패 시 즉시 화면 재조회 | 프로토타입에서 인위적으로 충돌 응답을 주입해 안내 문구·화면 갱신 확인 |
| 예약 취소 | destructive(normal) | 실수로 유효한 예약을 취소하지 않기 | confirm dialog에 좌석·시간 명시, 즉시 undo 대신 확인 요구 | 취소 플로우 사용성 테스트(오취소율 측정) |
| 좌석 현황 진입 | 세션 만료(edge) | 조작 도중 세션이 끊겨도 무엇을 하고 있었는지 잃지 않기 | 401 감지 즉시 로그인 화면 전환 + 재진입 유도 문구 | 세션 만료를 인위적으로 재현해 리다이렉트·안내 확인 |
| 좌석 현황 전체 | 전체 만석(edge) | 헛걸음 방지가 목적이므로 "지금은 없다"를 빠르게 알고 다음 행동(재조회) 결정 | 빈 그리드만 렌더링하지 않고 상태 문구 + 새로고침 제공 | 만석 fixture로 문구·재조회 동작 확인 |
