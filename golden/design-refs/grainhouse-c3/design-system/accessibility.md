# 접근성 계약

하한(협상 불가): 텍스트 4.5:1 · 상태를 전달하는 비텍스트 3:1 · **기능 보더는 기본 배경
(paper)과 행 hover 배경(paper-2) 양쪽에서 3:1** · focus-visible · 색 단독 전달 금지 ·
인터랙티브 타깃 44px(WCAG 절대 하한 24px 위의 실무 기준).

## 대비 계산표

방법: WCAG 2.x 상대 휘도 산식 수계산(2026-08-23, 소수 둘째 자리). 추정값 없음 — 전부 계산.
"판정"은 해당 용도의 하한 기준이다.

| 전경 | 배경 paper `#f3efe7` | 배경 paper-2 `#eae5da` | 용도 · 하한 | 판정 |
|---|---|---|---|---|
| ink `#1f1d19` | 14.67 | 13.39 | 본문 텍스트 · 4.5 | PASS |
| ink-2 `#575248` | 6.77 | 6.18 | 보조·마이크로 텍스트 · 4.5 | PASS |
| accent `#2b4a9e` | 7.11 | 6.49 | 텍스트·진행 세그먼트(비텍스트 3) | PASS |
| accent-hover `#23407f` | 8.67 | 7.92 | hover 상태 | PASS |
| on-accent `#fff` | 8.15 (accent 위) | 9.95 (accent-hover 위) | 버튼 텍스트 · 4.5 | PASS |
| rule-strong `#867e72` | 3.49 | 3.19 | **기능 보더** · 양쪽 3.0 | PASS |
| error `#9e2b2b` | 6.46 | 5.90 | 텍스트·보더 겸용 · 4.5 | PASS (파생) |
| success `#2b6b40` | 5.59 | 5.10 | 동상 | PASS (파생) |
| warning `#8a5a00` | 5.17 | 4.72 | 동상 | PASS (파생) |
| on-accent `#fff` | 7.41 (error 위) · 6.40 (success 위) · 5.93 (warning 위) | — | semantic solid 버튼 텍스트 · 4.5 | PASS (파생) |
| rule `#b5ad9c` | 1.94 | 1.77 | 장식 괘선 — 하한 비적용 | N/A |
| grid `#e0d9ca` | 1.23 | — | 장식 괘선·스켈레톤 — 하한 비적용 | N/A |

- **정정**: 승인 렌더 주석은 `--rule`을 "paper 대비 2.4"로 적었으나 계산값은 1.94다.
  장식 전용이라 판정은 불변이지만, 이 값을 근거로 rule을 기능 용도로 승격하지 말 것.
- **기능 보더 규칙의 유래**(프로브 실측 2026-08-23): `#8d8579`는 paper 3.18로 통과했으나
  paper-2 위 2.90으로 미달 → `#867e72`로 교정. 교훈을 일반화한 것이 이중 배경 규칙이다:
  **의미를 전달하는 보더·아이콘은 그것이 놓일 수 있는 모든 배경에서 3:1을 검증한다.**
  새 표면색(semantic subtle-bg 등)을 추가하면 그 위의 기능 보더 대비를 재계산해야 한다.
- semantic subtle-bg(`color-mix` 8%)는 아직 계산되지 않았다 — 구현 시 그 위의 텍스트·보더
  대비를 실측하기 전에는 사용 승인 불가.

## 색 단독 전달 금지

- 4세그먼트 미터: `role="img"` + aria-label("공정 4단계 중 N단계 …") **필수** + 인접 mono
  상태 주석 동행 (승인 렌더가 이미 이 패턴 — 유지가 계약이다).
- 진행(accent)과 완료(ink)의 구분은 색 외에 텍스트 주석("스캔 중" vs "업로드 완료")이 전달.
- 폼 오류 = error 보더 + 아이콘 + 구체적 메시지. 본문 링크 = accent + 밑줄.

## Focus · 타깃

- `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px }` 전역 —
  accent는 두 배경에서 6.49:1 이상으로 포커스 링 하한(3:1) 통과.
- 인터랙티브 최소 44×44px(`--size-target`): 내비 링크(렌더 42px → 44px로 상향 정규화),
  버튼, 폼 컨트롤(라벨 포함 히트 영역), 페이지네이션. 표 행 내 소형 액션도 히트 영역 24px
  미만 금지.

## 모션

- 유일한 애니메이션은 `--animate-ink`(진행 상태의 잉크 명멸, 무한 루프 전용 — 선언 목적은
  tokens.md §모션). `prefers-reduced-motion: reduce`에서 전면 정지 — 정지해도 상태는
  색 + 텍스트 주석으로 이미 전달되므로 정보 손실 없음(렌더 구현 확인).
- 인터랙션 전환 애니메이션은 시스템에 없다 — 추가하려면 원리 1과 충돌 검토 필요.

## Forced colors (Windows 고대비)

- 구조가 전부 실제 보더(1px 괘선)로 그려져 있어 forced-colors에서 형태가 보존된다 —
  괘선을 `background`나 그림자로 대체하지 말 것(보존성이 깨진다).
- 잉크 채움 상태(완료/진행 세그먼트·체크 채움)는 배경색이므로 강제 색상에서 소실된다 →
  해당 요소에만 `data-ink-fill` + `forced-color-adjust: none` (theme.code.css). 전역 해제 금지.

## 다크 모드 · 고대비 테마

- **다크 모드는 제공하지 않는다** — 원칙(다크 모드 절) 대신 라이트 단일: 승인된 매체 은유
  (인화지 위의 잉크 — "인화지 위에서는 발광이 성립하지 않는다")가 발광 표면과 양립하지
  않고, 브랜드-포워드 소비자 서비스로 재설계 비용 대비 근거가 없다. OS 다크 설정에서도
  paper 라이트를 유지한다.
- 고대비 필요 사용자는 forced-colors 경로로 대응한다(위 절) — 별도 high-contrast 테마를
  만들지 않는다.

## 텍스트 크기 예외의 경계

micro 9.5px(원칙 11px 하한 미달)는 mono caps + tracking 0.2em + ink-2(6.77:1) 조건의
overline 라벨 전용이다. 문장·인터랙티브 요소·단독으로 의미를 전달하는 정보에 쓰면
위반이다 — design-reviewer는 micro 사용처가 이 경계 안인지 본다.
