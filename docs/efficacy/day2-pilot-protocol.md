# Day-2 파일럿 프로토콜 — 하네스 vs 대화+push (반증 실험)

> 배경: 저자가 자기 하네스를 우회하고 실제 반복 개발을 대화+직접 push로 수행한다는
> 스모킹 건(2026-08-18 합의, 메모리 `harness-dogfood-gap`). 원인 진단은 "모든 가치가
> 서명 릴리스 단일 출구에 결박"이었고, 재진입 기계화 3층(reentry-map `5c0e157` ·
> SessionStart 훅 `34a8db9` · CLAUDE.md 마커 `c5a8343`)이 그 처방의 1단계였다.
> 이 파일럿은 그 처방이 실제로 작동하는지를 **저자의 실제 변경 건**으로 심판한다.
> 심판대에 서는 것은 게이트가 아니라 하네스다.

## 반증 가능 기준 (사전 고정 — 사후 변경 금지)

- 대상: tamiya 계열 실서비스(tamiya-motor-lab / tamiya-race-app / minicar-laptime)의
  **실제 변경 약 3건**을 재진입 경로(reentry-map 상황 A/B)로 수행한다.
- 합격: 3건 완료 후 저자가 자기 기준으로 "다음 변경도 이 경로로 하겠다"고 판단하면
  합격이다. **우회의 재발 여부 자체가 판정이다** — 파일럿 후 저자가 다시 대화+push로
  돌아가면 불합격.
- 불합격 시 조치(사전 합의): day-2 제품 재설계, 또는 하네스 정체성 주장을
  "0→1 그린필드·대형 변경"으로 축소(I1 — 실측이 주장을 이긴다).
- 이 파일은 라운드마다 실측을 append한다. 좋게 나온 라운드만 기록하는 것은 I1 위반이다.

## 측정 항목 (라운드당)

| 항목 | 출처 |
|---|---|
| 스폰 수·토큰(스폰 합계) | 프로젝트 `_workspace/04_qa/execution-telemetry.json` (계약: null 허용, 위조 금지) |
| 벽시계 시간(요청→검증 완료) | 세션 기록 |
| 실행 게이트·검증 목록 | 라운드 기록에 열거(생략은 생략이라 적는다) |
| 산출 receipt | change-scope 항목·구현 검증 증거·(승인 표면 썼으면) 승인 레코드 |
| 대화+push 대비 저자 체감 | 라운드 종료 시 저자 한 줄 판정(더 나음/비슷/더 나쁨) |

비교 기준선: 같은 규모 변경을 대화+push로 할 때의 관행 — 정밀 토큰 대조는 불가능하므로
(과거 대화의 토큰은 미계측) **저자 체감 + receipt 유무의 질적 차이**가 1차 판정이고,
토큰·시간은 참고 수치다. 이 한계는 정직하게 남긴다.
