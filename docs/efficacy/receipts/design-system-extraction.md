# 시안 → 디자인 시스템 → 파생 화면 — 완주 receipt (2026-08-23)

승인된 시안 **1장**에서 디자인 시스템을 추출하고, 그 시스템**만**으로 나머지 화면을 만든 뒤,
사용자 검토로 발견된 결함을 시스템에 되먹인 첫 end-to-end 실행 기록.
선행: `free-lane-divergence-probe.md`(시안 확정까지). fixture: `workspace/grainhouse`(gitignored).

**한 줄 요약**: 시스템은 새 화면을 결정하는 데 **대체로 충분**했고(파생 10건이 전부 예측된
자리에서 발생, 새 색 0개), 진짜 수확은 **사용자 검토가 드러낸 시스템 공백 12건**이었다.

## 1. 흐름

| 단계 | 산출 | 비용 |
|---|---|---|
| 시스템 추출(fable, 소유 경로) | `_workspace/02_design/design-system/` 5파일 — 토큰 48 · 원리 5 · 컴포넌트 인벤토리 · 접근성 계약 | 74,089 tokens · 16 tool uses |

## 2. 시스템이 충분했는가 — 파생 실측

- **파생 원소 10건**이 필요했고 **전부 `components.md` B("승인 렌더에 없음 — 원리에서 파생")
  목록 상부**에서 발생했다. 예측하지 못한 공백은 없었다.
- **새 색 0개 · 새 대비 계산 0건** — 모든 조합이 기존 계산표 안에서 해결됐고, 미계산이라
  사용 금지된 색(semantic subtle-bg)은 어디에도 쓰이지 않았다.
- 파생 결정이 전부 특정 원리 번호로 환원됐다(예: 빈 상태의 "grid 괘선 유지" → 원리 1의
  그라데이션 금지에서 파생 → 실제 보더 빈 행으로 구현, forced-colors 보존성도 우수).
- **원리가 색표가 아니라 생성 규칙으로 작동**했다는 증거: "빛나야 할 것 같은 요소를 만나면
  종이 위에 인쇄된다면 어떻게 생겼을지 묻는다"(원리 1)가 로딩 스피너 금지 → 잉크 명멸,
  스켈레톤 글로우 금지 → 대지색 블록으로 이어졌다.

## 3. 사용자 검토가 드러낸 것 — 시스템 갱신 12건

화면만 고치지 않고 **전부 시스템 문서에 반영**했다(계약의 왕복 규율: 지역 스타일로 때우지 않고
시스템을 먼저 갱신). 대부분이 "에이전트 실수"가 아니라 **시스템의 공백·오류**였다.

| # | 지적 | 진단 | 시스템 반영 |
|---|---|---|---|
| 1 | 폼이 답답하다 | 원리 5가 폼을 "양식지"로 규정했으나 **폭 토큰이 문서용 하나뿐** | `--size-form-max: 52em` 신설 |
| 2 | 그룹 제목이 작다 | **위계 역전** — 제목 9.5px < 라벨 10px. micro는 "overline 전용" 경계 위반이기도 | 폼 그룹 제목 = annot + ink 규정 |
| 3 | 버튼이 투박하다 | 패딩 협소 · 2줄 덩어리 · 전환 부재. radius 0은 별건(아래 4) | 버튼 패딩·전환·보조 버튼 무게 규정 |
| 4 | **radius 0의 근거는?** | 승인 시안의 **선언 부재**를 추출 단계가 금지 규칙으로 승격 — 아무도 0을 결정한 적 없음 | 네 값 렌더 비교 후 **스케일 도입**(sm 2 / md 4 / full). 내부 모순(“예외 없음” ↔ “라디오=원”) 동시 해소 |
| 5 | 한글 폰트가 제각각 | mono 스택에 **한글 폴백 부재** → 시스템 대체 폰트로 떨어지고 tracking이 그대로 적용돼 "이 름"처럼 벌어짐 | mono 스택 한글 폴백 + 한글 tracking 재검토 규정 |
| 6 | Pretendard로 교체 | (사용자 결정) | 전 문서·화면 교체 |
| 7 | 전체적으로 글자가 크다 | **서체 교체의 후과** — Pretendard는 x-height가 커서 같은 px이 크게 보임. 크기 값은 IBM Plex 기준이었음 | `font-size-adjust: 0.52` + **"서체 교체 시 스케일 재검증"** 규칙 |
| 8 | 선택 항목이 크다 | `--text-form`(16px, iOS 줌 방지)을 **입력값이 아닌 선택 라벨에** 적용 | form 토큰의 경계 명시 + 위계 자기점검 규칙 |
| 9 | 영문 서체가 갈린다 | 한 표 셀에서 `Ektachrome E100`(세리프) · `135·36컷`(세리프) · `412MB`(mono) 혼재 | **원리 3 기본값 반전** — 기본 mono, 세리프는 타이틀 전용 |
| 10 | 라인이 투박하다 | 구조선에 `--color-ink` 사용 — **본문 텍스트와 같은 농도** | `--color-rule-structural` 신설(5.10:1). 4단 위계 확립 |
| 11 | 기본 폰트색이 너무 검다 | `#1f1d19`(14.67:1)는 순검정에 가까워 웜페이퍼 위에서 딱딱 | 본문 잉크 `#413c34`(9.53:1) |
| 12 | 페이지 너비가 다르다 | 문서형 화면이 `<main class="prose">`에 폭 제한 → 페이지 틀 자체가 좁아짐 | **"폭은 화면이 아니라 요소가 정한다"** — 줄 길이 제한은 문단에만 |

부수: 액션 줄 오른쪽 정렬 규정(취소·확인을 한 덩어리로), 인풋 시각 높이 38px(클릭 타깃 44px 유지),
반응형 표의 컬럼 우선순위(핵심 4개 고정, 부차 2개 단계 접힘).

## 4. 접근성 — 기계 검증

- 시스템의 대비표(수계산 24쌍)를 **스크립트로 전수 재검증: 문서값 불일치 0 · 하한 미달 0**.
- 색을 두 번 바꾼 뒤(구조선 신설·본문 잉크 완화) **재검증 14/14 PASS**.
  위계: 본문 9.53 > 구조선 5.10 > 기능 보더 3.49 > 장식선 1.94.
- 접근성 하한을 **한 번 깨뜨렸다가 되돌린 기록**: 폼 컨트롤을 15px로 낮췄으나 이는
  iOS 줌 방지 하한(16px) 위반 → 원복하고 `font-size-adjust`로 광학 보정. 하한은 협상 불가다.

## 5. 정직한 한계

- **fixture 1건·형태 1종**(브랜드-포워드 소비자). 어드민/대시보드 형태 재현은 미실증 —
  이 receipt의 일반화는 **명명 수준**이다.
- 파생 화면은 **정적 HTML**이다. 실제 스택(React·tailwind-shadcn) 구현에서 같은 시스템이
  성립하는지는 Phase 3의 몫이며 여기서 증명되지 않았다.
- 검토는 **사용자 1인의 육안**이다. 통계가 아니라 12건의 선호·결함 실측이다.
- 시스템 내부 모순 2건은 에이전트가 **스스로 발견해 보고**했다(tokens "radius 0 예외 없음" ↔
  components "라디오=원"; 한글 양수 자간 금지 ↔ 렌더의 실제 적용). 자기 발견이 작동한 사례지만,
  **모순을 만든 것도 같은 추출 과정**이었다.
- 대비 계산은 스크립트로 검증했으나, **"보기 좋은가"는 기계가 판정하지 않는다** — 12건 중
  대비 위반은 2건뿐이고 나머지 10건은 전부 사람 눈이 잡았다(파일럿 2 A-1의 비대칭 재확인).

## 6. 후속

1. `design-principles-research.md` 개정 — 타일의 역할 재정의(선행 receipt의 후속 1번).
2. **어드민/대시보드 형태에서 같은 흐름 재현** — 명명 수준 → 실증 승격 조건.
3. 대비 검사 스크립트의 도구화 — 이 세션에서 임시 스크립트로 결함 3건(1.58:1 · 2.90:1 ·
   문서-실측 불일치)을 잡았다. 발산·이식·시스템 갱신 단계의 상시 검사로 승격할 가치가 있다.
4. `IMPLEMENTATION-VERDICT` 축별 대조표는 이번 라운드에서 산출하지 않았다(정적 HTML 단계라
   구현 검증 대상이 아님) — Phase 3 구현 시 필수.
