## 2. 판정 — 증명된 것과 증명되지 않은 것

분류 기준: 실행 로그·receipt가 남아 있으면 실측, 아니면 미측정.

### 실측 — 근거 있음

- **탐지 효능** — 게이트 로직 단위 46/46, 합성 리플레이 1,200 샘플, 라이브 ON 발화
  1건. 게이트가 *위반을 탐지한다*는 명제는 receipt로 닫혔다.
- **서비스 규모에서의 발화** — 그린필드 파일럿 2회에서 게이트가 실제로 작동했고,
  2차 파일럿은 하네스 자체 결함 14건을 커밋으로 남기며 T0에 도달했다.
- **티켓 왕복 라이브 실증** — 배포된 플러그인 환경에서 실제 GitHub repo로 일괄 청구
  → 보드 → 픽업 → PR → 링크 → 머지 → 자동 종료까지 완주.
- **이번 세션 자체가 증거** — 줄 수 예산·콘솔 승인 가드·시안 세대 회귀에서 게이트가
  실제 위반 3건을 잡았고, 라이브 검증이 필드명 드리프트와 1.34:1 대비 위반 2건을
  잡았다.

### 미측정 — 근거 없음

- **결과 효능** — 게이트 ON이 OFF보다 완주율·품질이 높은가는 *측정된 적이 없다*.
  `docs/efficacy/receipts/synthetic-replay.md`가 이 공백을 스스로 명시한다. 이것이
  포지션 전체를 지지하거나 반증할 단 하나의 실험이다.
- **프로필 2종** — `react-vite-spa`·`next-app-fullstack`은 compatible 표기일 뿐
  인증 receipt가 없다.
- **자동 빌더의 단독 완주** — 파일럿에서 빌더는 오케스트레이터 개입 없이는 runaway
  또는 절단됐다. 하네스는 사람이 지켜볼 때 작동한다.
- **계약 드리프트의 기계 탐지** — 이번 세션의 규약 모순(React.FC 잔존 8곳 등)은
  게이트가 아니라 사람이 발견했다.
- **비용 정당화** — 앱당 ~12.7M 토큰이 그만한 값을 하는지에 대한 근거는 없다.
- **저자 자신의 사용** — 도그푸드 갭이 기록돼 있다. 상류 가치가 단일 서명 출구에
  결박돼, 저자 본인이 하네스를 우회했다.

## 4. 가장 무거운 반대 증거 — 측정이 무너진 자리

> 개발자는 19% 느려졌다. 그러면서 20% 빨라졌다고 믿었다.

METR의 2025-07 연구 결과다. 2026-02 후속에서는 방향이 반전되는 듯했지만, METR
스스로 그 신호를 **신뢰할 수 없다**고 선언했다 — AI 없이 일하기 싫어하는 참가자의
이탈, 개발자 30~50%가 AI가 크게 도울 태스크를 아예 제출하지 않는 회피, 시급 인하로
악화된 선택 편향, 그리고 여러 에이전트를 동시에 돌리면 시간 측정 자체가 성립하지
않는 문제. 결론은 "AI가 빠르다"가 아니라 **"측정 방법이 무너졌다"**였다.

이 발견은 web-harness에 양방향으로 작용한다. 한쪽으로는 I1(주장과 증명을 섞지
않는다)이 왜 존재하는지를 정확히 설명한다 — 체감과 실측의 괴리가 이 분야의
기본값이다. 다른 한쪽으로는 하네스 자신을 겨눈다: **게이트가 있다는 사실을 효능의
증거로 착각하는 것**이 정확히 같은 함정이다.

명시해 둔다. 이번 조사에서 "증거 게이트 접근이 METR이 지적한 문제를 해결한다"는
인과는 **확인되지 않았다**. web-harness에 대한 독립적 생산성·품질 실측은 존재하지
않는다.

## 5. 권고

순서 기준: 미증명 항목 중 해소했을 때 다른 판정을 가장 많이 바꾸는 것부터.

1. **결과 효능 A/B를 실행한다.** 게이트 ON vs OFF의 완주율·결함율. 지금 열려 있는
   유일한 근본 공백이고, 나머지 모든 주장의 지지대다. 자원 결정(10~20M 토큰)이 이미
   대기 중인 항목이다. 이걸 닫지 않으면 §2의 미측정 목록은 다음 감사에서도 그대로
   남는다.
2. **파이프라인 깊이를 요청 규모에 연동한다.** 업계 절충안은 "풀 오케스트레이션은
   breadth-first 고위험 작업에만"이다. 모든 요청에 같은 깊이를 강제하는 구조가
   12.7M/앱의 직접 원인이다. Iterate mode가 이미 그 방향의 축소판이므로 확장할
   자리는 있다.
3. **산문 계약을 기계 검사로 옮긴다.** 3,838줄 중 어디부터인지는 이미 정해져 있다 —
   §4 등록부에서 미해결로 표시된 26행이 우선순위 목록 그 자체다. 이번 세션의 규약
   모순을 사람이 발견했다는 사실이 이 항목의 근거다.
4. **프로필 2종을 인증하거나 범위를 좁혀 선언한다.** certified 1 / compatible 2
   상태는 "3개 프로필 지원"으로 읽히기 쉽다. 인증 receipt를 발급하거나 지원 범위를
   1종으로 명시하는 편이 I1에 부합한다.
5. **카탈로그에서 차별점이 보이게 한다.** 스킬 3,000개 규모 카탈로그에서 "증거
   게이트"는 설명하지 않으면 보이지 않는다. 기술 문제가 아니라 포지셔닝 문제이고,
   비용도 가장 싸다.

**참고 채택 후보** — Protocol-Driven Development 논문의 어휘(불변식·연속 증거)는
하네스 설계를 외부 표준 언어로 재서술할 때 쓸 수 있다. Figma Visual Reviewer의
"개선율 임계 미만이면 자동 중단하고 사람 판단으로 넘김"은 시안 승인 루프의 무한
반복 방지에 바로 적용 가능하다.
