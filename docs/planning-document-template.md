# 기획 문서 템플릿

아래 한 장을 채워 주시면 됩니다. 대부분 이미 쓰시는 것들이고, **실제로 더해지는 건 둘뿐**입니다.

| | |
|---|---|
| **더해지는 것 하나** | **화면마다 조건을 적는다** — 아무것도 없을 때, 잘못됐을 때, 권한이 없을 때 무엇이 보이는가 |
| **더해지는 것 둘** | **기능마다 완료 기준을 적는다** — 무엇이 되면 끝났다고 할 수 있는가, 눈에 보이는 것으로 |

> 이미 PRD·슬라이드 덱이 있으시면 **다시 쓰지 마십시오.** 맨 아래
> 「이미 문서가 있으시면」을 보십시오.

## 양식

**모르는 항목은 비워 두십시오.** 채우라고 재촉하지 않습니다 — 비어 있으면 나중에 **필요한
것만 따로 여쭙습니다.** 지어내서 채우면 그게 결정으로 굳습니다.

```markdown
# <서비스 또는 기능 이름>
판본: v0.1 (2026-09-08)

## 무엇을, 누구를 위해

- 대상:
- 사용자와 목표:
- 지금 무엇이 어려운가:
- 무엇이 관찰되면 성공인가:

## 화면

| 화면 | 한 줄 설명 |
|---|---|
|  |  |
|  |  |

## 화면마다

### <화면 이름>

- 3초 안에 얻어야 하는 것: ①  ②  ③
- 아무것도 없을 때 보여줄 것:
- 잘못됐을 때 보여줄 것:
- 권한이 없는 사람에게 보여줄 것:
- 그 밖의 조건 (있으면):

## 기능마다

### <기능 이름>   (반드시 / 있으면 좋음 / 이번엔 뺌)

- 어느 화면에서:
- 어떻게 동작하는가:
- 무엇이 되면 완료인가
  - 정상:
  - 안 되는 경우:
  - 취소할 때:
```

- **해당하지 않는 조건은 비우지 말고** `해당 없음(사유)`로 적어 주십시오 — 빈 칸은
  「이 조건이 없다」가 아니라 「아직 안 정했다」로 읽힙니다.
- 화면 상태는 **사용자에게 보여줄 내용**으로. ✗ 빈 상태 컴포넌트 / ✓ 아직 등록된 항목이
  없다는 안내와 첫 등록 버튼
- 완료 기준은 **눈에 보이는 것**으로. ✗ 잘 동작한다 / ✓ 목록에 새 행이 추가되고 상세에도 반영된다
- **「안 되는 경우」를 빠뜨리기 쉽습니다.** 여기서 안 적으면 아무도 안 적습니다.
- **「이번엔 뺌」은 지우지 말고 그대로 두십시오** — 지우면 「뺐다」와 「원래 없었다」를
  구별할 수 없습니다.

## 채운 예시

```markdown
# 사내 세미나 예약
판본: v0.1 (2026-09-08)

## 무엇을, 누구를 위해

- 대상: 세미나 신청·취소와 운영자 명단 관리
- 사용자와 목표: 임직원이 세미나를 찾아 신청하고, 운영자가 명단을 받는다
- 지금 무엇이 어려운가: 메일과 스프레드시트로 받아 담당자가 수기로 정원을 센다
- 무엇이 관찰되면 성공인가: 정원 확인 문의가 절반으로 준다

## 화면

| 화면 | 한 줄 설명 |
|---|---|
| 신청 목록 | 다가오는 세미나를 날짜순으로 |
| 신청 상세 | 설명과 신청 버튼 |

## 화면마다

### 신청 목록

- 3초 안에 얻어야 하는 것: ① 다가오는 일정 ② 정원 대비 신청 수 ③ 마감까지 남은 시간
- 아무것도 없을 때: 예정된 일정이 없다는 안내와 지난 일정 보기 링크
- 잘못됐을 때: 마지막으로 본 목록을 그대로 두고 상단에 재시도 배너
- 권한이 없는 사람에게: 해당 없음 (전 임직원이 볼 수 있다)
- 그 밖의 조건: 정원이 찼을 때 — 신청 버튼 대신 「마감」 표시

## 기능마다

### 신청하기   (반드시)

- 어느 화면에서: 신청 목록, 신청 상세
- 어떻게 동작하는가: 마감 전이고 정원이 남아 있을 때만 버튼이 활성이다.
  누르면 확인 창이 뜨고, 확인하면 신청 수가 즉시 올라가며 버튼이 「신청 취소」로 바뀐다.
- 무엇이 되면 완료인가
  - 정상: 신청 후 목록의 신청 수가 1 늘고 내 신청 내역에 그 일정이 나타난다
  - 안 되는 경우: 마감이 지났으면 버튼이 비활성이고 "신청이 마감되었습니다"가 보인다
  - 취소할 때: 확인 창에서 취소하면 아무것도 바뀌지 않고 창이 닫힌다
```

## 있으면 더 좋은 것

없어도 진행됩니다. 있으면 되묻는 횟수가 줄어듭니다.

### 시안이 있으면

파일과 함께 **어느 화면·어느 조건인지** 한 줄씩 적어 주십시오.
Figma는 파일 링크가 아니라 **프레임 링크**를 주십시오.

```markdown
| 시안 파일 또는 Figma 프레임 | 어느 화면 | 어느 조건 |
|---|---|---|
|  |  | 기본 |
|  |  | 아무것도 없을 때 |
```

시안이 없는 조건이 있어도 정상입니다. 비워 두시면 승인 때 여쭙습니다.

### 분기가 복잡하면

순서도가 있으면 그림도 주시되 **연결을 문장으로도** 적어 주십시오 —
그림의 화살표는 기계가 읽지 못합니다.

```markdown
### 분기: <이름>

- 조건: <무엇을 보고 판단하는가>
  - <값 A> → <어느 화면으로 가고 무엇이 보이는가>
  - <값 B> → <어느 화면으로 가고 무엇이 보이는가>
  - 그 밖 / 판단할 수 없을 때 → <무엇이 보이는가>
```

**「그 밖 / 판단할 수 없을 때」를 꼭 채워 주십시오.** 순서도에서 가장 자주 빠지고 개발에서
가장 자주 문제가 되는 자리입니다.

### 화면 상태를 더 자세히

위 네 가지 말고도 정해 두신 것이 있으면 같은 자리에 줄만 더하시면 됩니다.

```markdown
- 불러오는 중에 보여줄 것:
- 일부만 불러왔을 때 보여줄 것:
- 모바일에서 달라지는 것:
- 밀도: 빽빽하게 / 표준 / 여백 있게
```

### 데이터와 제약

```markdown
- 이번 단계 데이터: 가짜 데이터 / 개발 DB 읽기만 / 실데이터 읽기만 / 연결은 나중
- 실제 연결로 넘어가는 조건:
- 다루면 안 되는 것 (개인정보 등):
- 브랜드 제약 (색·로고·폰트): 있음 / 없음
- 다크모드: 필수 / 선택 / 불필요
- 주 사용 기기: 데스크탑 / 모바일 / 둘 다
```

## 안 쓰면 어떻게 되나

빠뜨려도 **진행은 됩니다.** 다만 대가가 어디서 나타나는지가 다릅니다.

| 빠진 것 | 무슨 일이 일어나나 |
|---|---|
| 화면마다 조건 | 빈 화면·오류 화면을 **개발자가 그 자리에서 정한다** |
| 기능마다 완료 기준 | 「완료」의 기준이 없어 **팀에 나눠줄 수 없다** |
| 「이번엔 뺌」 표시 | 뺀 기능이 살아 있는 요구로 읽혀 **구현된다** |

### 다 못 채워도 되는 이유

부분만 주셔도 됩니다. 받은 부분은 그대로 쓰고 빠진 부분만 채운 뒤 **채운 것은 「가정」으로
표시**합니다. 그리고 **작성하신 분만 답할 수 있는 것**은 따로 질문지로 만들어 되묻습니다 —
기술 용어 없이, 문서 어디를 보면 되는지와 답이 없으면 무엇이 막히는지가 함께 적힙니다.
**그 질문지에만 답하시면 됩니다.**

## 이미 문서가 있으시면

**다시 쓰지 마십시오.** PRD·슬라이드 덱이 있으면 그대로 주시면 됩니다.

글로 적힌 것은 거의 다 읽힙니다. 다만 **그림 안에 있는 것**은 못 읽습니다 — 시안 이미지와
순서도의 화살표입니다. 그래서 **이 셋만** 따로 주시면 됩니다:
**화면마다 조건** · **시안이 어느 화면인지** · **분기를 문장으로**.

---

## 부록 — 쓰지 않으셔도 되는 것

아래는 하네스가 알아서 만듭니다. 따라 쓰지 마십시오.

- **화면 ID**(`PAGE-001` 같은 것) — 화면 이름만 주시면 됩니다
- **기술 표기**(`state:empty` 같은 것) — 위 항목 이름 그대로 쓰시면 됩니다
- **테스트 형식**(Given/When/Then) — 평서문으로 쓰시면 하네스가 옮깁니다
- **화면 크기·색상값·컴포넌트 이름** — 디자인 단계가 정합니다

> 하네스의 계약을 전부 읽고 도는 **하네스 자신의 정규화 프로그램조차** 그 표기를 틀리게
> 씁니다(2026-09-08 실측 — 첫 열을 `PAGE-001 세미나 목록`으로 써서 자기 검사기에 걸렸습니다).
> 사람에게 요구할 형식이 아닙니다.
