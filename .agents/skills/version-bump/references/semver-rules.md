# Semantic Version Rules

`version-analyzer`가 버전 bump를 결정할 때 사용하는 판단 기준.
신호가 여러 개 있으면 **가장 높은 등급**으로 결정한다.

먼저 versioned public contract가 있는지 확인한다. npm 라이브러리는 SemVer를 적용한다. private 웹앱은 조직의 release/version 정책이 있을 때만 app version을 변경하며, 내부 구현 변경을 소비자 breaking change로 오판하지 않는다. 신규 스캐폴딩 직후에는 자동 bump하지 않는다.

---

## MAJOR (x.0.0)

다음 중 하나라도 해당하면 major:

### 공개 계약의 breaking change
- 공개 export 삭제 또는 이름 변경
- 함수 시그니처 변경으로 기존 호출 코드가 깨짐
  - 예: 필수 파라미터 추가, 파라미터 타입 narrowing, 반환 타입 변경
- 기본 동작 변경 (opt-in이 아닌 무조건 적용)
- 문서화된 지원 runtime/Node/browser 최소 버전 상향
- 여러 소비자가 사용하는 공개 HTTP/event/schema 계약의 비호환 변경

내부 React/Router/MUI 교체, CSR→SSR 구현 전환, 모노레포 전환, 큰 기능 추가는 그 자체로 major가 아니다. 외부 소비자 계약이 깨지는지를 판단한다.

---

## MINOR (0.x.0)

다음에 해당하면 minor. major 신호가 없을 때만 적용:

### 새 기능 추가
- 기존 도메인 안에서 새로운 기능/화면/컴포넌트 추가
  - 예: 차트 필터 추가, 엑셀 내보내기 추가, 알림 센터 추가
- 기존 기능을 크게 개선 (UX 흐름 변경, 성능 최적화 전면 적용)
- 새 API 엔드포인트 연동
- 새 설정 옵션, 새 페이지, 새 위젯 추가

### 라이브러리 전용 추가 기준
- 새 export 추가 (기존 코드에 영향 없음)
- 기존 함수에 선택적 파라미터 추가
- 새 유틸 함수 / 새 컴포넌트 추가

---

## PATCH (0.0.x)

다음에 해당하면 patch. major·minor 신호가 없을 때만 적용:

### 간단한 수정
- 버그 수정 (기능 동작은 그대로, 잘못된 동작만 고침)
- 타입 오류 수정
- UI 오타, 레이블 문구 수정
- 스타일 미세 조정 (레이아웃 깨짐 수정, 색상 보정)
- 성능 미세 개선 (기능 변화 없음)

### 코드 품질
- 리팩토링 (외부 동작 변화 없음)
- 테스트 추가/수정
- 의존성 패치 버전 업데이트 (예: `1.2.3` → `1.2.4`)
- 빌드 설정, CI 설정 수정
- 문서 수정

---

## 판단이 애매한 경우

| 상황 | 판단 | 이유 |
|---|---|---|
| 라이브러리 마이너 버전 업 (예: MUI 7.1 → 7.2) | patch | API 변경 없음 |
| 앱 내부 라이브러리 메이저 업 | patch 또는 release-policy | 외부 계약 변화가 없으면 major 아님 |
| npm 라이브러리의 peer dependency 지원 범위 비호환 변경 | major | 소비자 설치/사용 계약 변경 |
| 기존 화면 전면 리디자인 (기능 동일) | minor | 기능 추가 없지만 UX 큰 변화 |
| 기존 화면 전면 리디자인 (기능도 추가) | minor 이상 | 추가 기능 규모에 따라 결정 |
| 의존성 보안 패치 | patch | 동작 변화 없음 |
| 환경변수 추가 (기능 연동) | minor | 새 기능 활성화 |
| 환경변수 추가 (설정값만) | patch | 동작 방식 변화 없음 |

## 버전 결정 흐름

```
변경 목록을 보고 아래 순서로 확인:

0. versioned public contract 또는 app release policy가 있는가?
   NO  → bump 없음
   YES → 다음

1. 외부 소비자의 major 신호가 하나라도 있는가?
   YES → major
   NO  → 다음

2. minor 신호가 하나라도 있는가?
   YES → minor
   NO  → 다음

3. 그 외 → patch
```

## CHANGELOG 항목 분류

결정된 버전과 함께 아래 섹션으로 분류해서 작성한다:

```markdown
## [1.3.0] - 2025-07-08

### Added
- 신규 기능 목록

### Changed
- 기존 기능 변경 목록 (breaking이면 ⚠️ 표시)

### Fixed
- 버그 수정 목록

### Removed
- 제거된 기능 (breaking이면 ⚠️ 표시)

### Deprecated
- 곧 제거될 기능
```
